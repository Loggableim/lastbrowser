Privacy Policy

Lastbrowser stores browser profiles on your device. This policy explains when Lastbrowser contacts external services and what data it shares.

1. Local browser profiles

Browser profiles include history, bookmarks, open tabs, passwords, cookies and saved credentials. On Windows, the installed and portable versions use %APPDATA%\Lastbrowser for new default profiles. If an earlier version created a profile under %APPDATA%\@lastbrowser\desktop, Lastbrowser uses that directory by default. You can choose a different profile path with the --user-data-dir launch option. Lastbrowser does not operate a central service to sync these profiles. For the MSIX edition, Windows can redirect newly written data to per-user package storage. Windows can remove those files when the Store package is uninstalled.

In the installed Windows version, you can set up encryption for selected Spaces. After setup, Lastbrowser stores the selected profiles in encrypted vaults. This feature requires WinFsp. Hardware-backed mode also requires TPM 2.0.

2. Background network connections

LastBrowser can make background requests at startup. The ad blocker downloads filter lists and scriptlet resources from GitHub's raw content host when its cache needs refreshing. Turning off the ad blocker using the shield also turns off future filter downloads. The Castlabs Chromium runtime can contact Google's component update service at update.googleapis.com for Widevine. The --disable-component-update launch option turns off Chromium component updates and can prevent protected-media playback. For downloads outside the Microsoft Store, the app updater can contact GitHub Releases. You can turn off those automatic app updates in Settings. For the MSIX edition, the Microsoft Store manages app updates.

The Lastbrowser desktop app does not use analytics telemetry to track your browsing activity. The services listed above and the sites and services you open through the app receive standard connection data such as your IP address.

3. Artificial Intelligence & Model Privacy

When interacting with Nova AI, you control where data travels:

  • Local Ollama models: Inference runs locally when both the model and Ollama endpoint run on your own computer. A remote Ollama endpoint or cloud model may process requests outside your computer.
  • Ollama Cloud and external AI providers: These connections send your requests and the context supplied for the task, such as selected tab content, to the selected provider. Credentials required for the connection are used to authenticate it. That provider's privacy policy and retention periods apply. A cloud connection is not offline processing.
  • Tasks and goals: Starting an AI task or ongoing goal can result in multiple requests within that task. Data transfers depend on the enabled providers and the tools and content authorized for the task.

When you report an AI reply, Lastbrowser opens a draft in your email app addressed to support@lastbrowser.com. The draft contains the selected reason and any comments you enter. It does not automatically include the AI reply or your prompt. When the draft opens, Lastbrowser saves the reason and any comments locally in the app profile and keeps up to 100 recent entries. This also happens if you leave the draft unsent. If you send the email, support receives your sender address and email contents to review the report and respond when needed.

4. Data Subject Rights (GDPR)

You can delete locally stored browsing data through Lastbrowser settings. Local deletion does not remove data already sent to external AI providers. Access and deletion requests for that data are governed by the relevant provider's privacy policy.
