## External sources and open decisions

Microsoft's current [Visual Studio 2026 redistribution list](https://learn.microsoft.com/en-us/visualstudio/releases/2026/redistribution) says individual VC runtime binaries can be redistributed only subject to Visual Studio license terms and that distribution is limited to licensed Visual Studio users. The [Visual C++ redistribution guidance](https://learn.microsoft.com/en-us/cpp/windows/redistributing-visual-cpp-files?view=msvc-170) repeats that constraint; the [Visual C++ Runtime terms](https://visualstudio.microsoft.com/license-terms/vs2022-cruntime/) and [Visual Studio licensing directory](https://visualstudio.microsoft.com/license-terms/) are relevant primary documents. The local original `REDIST-MSVC.txt` is only a pointer to the current REDIST list. No source or hash can determine whether the actual distributor/operator satisfies the applicable licensed-user, Community-edition eligibility, and end-user terms. Before redistributing the three DLLs, obtain a documented determination from the license holder/legal reviewer, or choose the alternatives below. Do not change the blocker to true based on this report.

Choices if that gate is not cleared:

1. Keep the Local-AI runtime unavailable in distributed builds and omit its CRT/runtime payload; retain cloud/existing providers.
2. Ship a Microsoft-provided redistributable installer only after its own license and unattended/offline installation model are reviewed; this is not equivalent to app-local portable closure and may require elevation/restart.
3. Have a qualified reviewer confirm the distributor's entitlement and exact files/terms, then record the decision, original source, file identity, and notice/UI proof. This report is not that legal review.

The repository's runtime notices are linked to llama.cpp and bundled native components. Exact source/license equivalence and complete notices in the actual UI remain explicitly unverified. Compare the pinned upstream source/license and every runtime dependency to the shipped notices; verify the actual in-app third-party notices view, reachable from the product UI, before changing the gate.

Models are a separate licensing boundary from the llama.cpp executable. The local integration catalog names LiquidAI models but does not by itself establish a model artifact revision or permission to redistribute that artifact. For example, the [LiquidAI LFM2.5-1.2B-Instruct model card](https://huggingface.co/LiquidAI/LFM2.5-1.2B-Instruct) identifies `lfm1.0`; obtain the exact pinned model revision's LICENSE and evaluate its conditions before any model weights are bundled or redistributed. Keep model download/inference claims separate from runtime binary packaging. A downloaded model's hash proves identity only.

Windows Sandbox is documented by Microsoft as a disposable hypervisor-isolated environment; requirements and configuration are in [Use and configure Windows Sandbox](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-configure-using-wsb-file). The current repo `.wsb` disables networking and maps the checkout read-only, which is appropriate for the CRT guest check. A clean image must be shown not to have the three VC CRT DLLs in `C:\Windows\System32`; otherwise the guest script's negative control is inconclusive.

## Post-freeze execution plan

Run after all product streams have stopped changing files. Keep a fresh, uniquely named output directory; preserve existing `output` and release directories. First capture `git status --short`, HEAD, and hashes for the source files/manifests. Review the final diff and ensure the four streams have no pending edits. Do not stage, commit, publish, or overwrite prior artifacts as part of this sequence.

1. **Source bundle and notices:** from repository root, run the focused Local-AI bundle/setup checks and source validation after freeze:

   ```powershell
   python -m pytest services/sidekick/tests/test_local_ai_native_bundle.py services/sidekick/tests/test_local_ai_setup.py services/sidekick/tests/test_local_ai_setup_leaf.py services/sidekick/tests/test_local_ai_bootstrap.py
   powershell -NoProfile -ExecutionPolicy Bypass -File scripts/verify-local-ai-crt.ps1 -RuntimeDir apps/desktop/runtime/local-ai/b11377-cpu -ManifestPath apps/desktop/runtime/local-ai/b11377-cpu/runtime-build-manifest.json -ReportPath output/<unique-run>/source-crt.json
   ```

   The CRT script executes the source runtime; run only after product freeze and only when that execution is authorized. Require manifest hashes/sizes/architecture and app-local resolution to pass. Record any in-box Windows dependency distinctly. A successful host run still does not close the clean-Windows gate.

2. **Build one new unsigned offline package:** prepare a unique output name and run the repository's installed-dependency offline preview path, not a network install or external clone. `package-feature-preview.cjs` creates an unpacked directory; `package-dist-preview.cjs` consumes a verified unpacked directory to produce NSIS and portable artifacts. Inspect each script's current arguments/guards after freeze before invocation and set the run's output path so it cannot collide with existing previews. Confirm zero attempted network calls, exact `extraResources` inventory, package manifest parity, and no secrets/database/config files. Then run `python scripts/verify-packaged-integration.py` against the new unpacked resource tree if its current CLI supports the path; read its `--help`/source first. Re-run the CRT verifier against `win-unpacked\resources\apps\desktop\runtime\local-ai\b11377-cpu` and save a report under the unique run directory.

3. **Unpacked launch and portable:** with a disposable test profile and no user data, run `scripts/probe-preview-executable.cjs` against the new unpacked executable and `scripts/probe-portable-executable.cjs` against the newly produced portable executable, after inspecting their current CLI and cleanup behavior. Capture exit code, process shutdown, service health, artifact hashes, and report paths. This proves only those test launch paths. Do not test with a production profile or infer model inference from backend-ready status.

4. **Clean Windows CRT closure:** only when a Windows Sandbox or VM already exists or has been separately provisioned and its use is authorized, open the checked-in `scripts/test-local-ai-closure.wsb`. It maps the repository read-only, disables networking, and invokes `scripts/guest-verify-crt.ps1`. Confirm the guest reports zero `msvcp140.dll`, `vcruntime140.dll`, and `vcruntime140_1.dll` in `System32`; require a negative-control failure without app-local CRT and positive `--version`/`--help` with app-local CRT, including loaded module paths. If the guest is contaminated, mark inconclusive and obtain a clean base image; do not certify. This closes dependency loading only, not inference or licensing.

5. **Installer install/uninstall:** install the new NSIS artifact into an isolated user-only test account/VM, choose a non-default path containing spaces, launch and verify product/backend health, then uninstall and inspect only that disposable account/VM for residual application files/shortcuts. Record whether any elevation/reboot occurs. Never run the installer on the user's primary machine for this audit. The earlier preview did not install the host system and therefore is not this proof.

6. **Local manual upgrade/restart:** in an isolated disposable VM, use two post-freeze, version-distinct local NSIS installers (unsigned local builds are sufficient for this manual path). Install vN, create a disposable profile with sentinel settings and test state, run vN+1 installer over the same installation, then verify the app closes/restarts as expected, reports vN+1, and preserves the profile data. Record installer hashes and any prompts/elevation. This proves local installer upgrade behavior only; it does not prove auto-update feed operation or signature trust.

7. **Live auto-update/restart:** proving the built-in updater requires an available reachable update feed and artifacts/signatures accepted by the updater's trust policy, plus appropriate release authorization. In an isolated VM, install vN, preserve a disposable profile, exercise check/download/install/restart from the feed, then verify process exit/relaunch, version transition, app-data preservation, and signature/hash validation. Test rollback/failure behavior if supported. A local `publish never` preview has no update-feed evidence. This preparation task performs no signing, upload, publication, or release/account changes; those are externally blocked until separately authorized.

8. **Final evidence bundle:** for each artifact, record source HEAD and dirty diff identity, package command/flags, exact file inventory, SHA-256, signatures (if a separately authorized signed release), all reports, VM base image/Windows version, install/upgrade scenario, and observed limitations. Keep unsigned preview evidence clearly labeled as preview. Only make `msvc_dependency_closure_verified` or license UI/source-equivalence claims after the exact gate evidence and required review exist; the licensing approval remains a human/legal decision.
