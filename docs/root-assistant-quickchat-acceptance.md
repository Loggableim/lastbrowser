## Quickchat privacy and reset behavior

`services/sidekick/web/api/quickchat.py` creates a private session with `session_kind="quickchat"` and a stable quick-chat identity. Both session-list paths filter that kind (`services/sidekick/web/api/models.py`), while ordinary sessions remain listed. `test_quickchat.py` verifies summarized prompt input opens a private stream and separately verifies list exclusion, stop cancellation preserves the transcript, reset removes only the private session, and mismatched scope/stream does not cancel. The Main controller tests verify its SSE reader closes on exact reset and rejects a late event. The new cross-controller test extends this to show an Assistant response remains accepted after Quickchat reset.

Quickchat is reset when browser profile, Space path, or backend profile changes; `App.tsx` uses its generation, QuickChat ID, stream ID, and full scope tuple to reject delayed tokens. Assistant state uses a separate `assistantScopeKey` and persistent conversation identity. This pass found no cross-scope or reset regression in the focused tests, but did not prove the mounted UI's A→B→A token race.
