# Scheduler and Nova/Swarm governance acceptance (2026-10-05)

Scope: focused source review and offline tests for A19, A22, A24, A35 and A39 from `independentagent.md`. This is not a package or live-app acceptance.

## Findings

- **A19 — duplicate starts / scheduler race: PASS, focused.** The scheduler occurrence is claimed inside the independent-store transaction and has a uniqueness-backed durable key (`runtime/independent/scheduling.py:151`; `runtime/independent/store.py:1022`). The run request id is deterministically derived from definition ID, schedule revision and planned UTC time (`scheduling.py:154`). Existing sequential stale-cursor retry coverage passed. New `tests/test_root_scheduler_governance.py` concurrently runs two ticks for one due occurrence and confirms exactly one run and one schedule event.
- **A22 — exhausted budget: PASS, focused.** Provider requests, measured tokens, active time and tool calls have bounded `Budget` fields (`runtime/independent/contracts.py:191`). Existing controlled-provider test confirms the second request is refused at a one-request limit and the run reports `provider_request_budget_exhausted` (`tests/test_independent_runs.py::test_provider_budget_exhaustion_prevents_next_request`). Nova browser claims also cap provider calls and claim each request once (`runtime/independent/governance.py:127-165`; `tests/test_independent_governance.py::test_real_manager_native_admission_budgets_file_claims_and_verified_terminal_release`). Delegation tests enforce the iteration budget before creating child work (`tests/test_child_delegate_stream.py::test_budget_and_foreign_parent_db_fail_closed`). These are bounded unit/integration seams, not full Assistant-to-agent end-to-end proof.
- **A24 — Europe/Vienna DST and missed ticks: PASS, focused.** `next_occurrence` resolves wall time in the configured IANA zone, skips nonexistent spring-gap minutes, chooses fold 0 only, and returns UTC (`scheduling.py:25-41`). A missed occurrence is recorded once; default `skip` avoids enqueueing, while `one_catch_up` enqueues at most the single claimed occurrence. Cursor advancement is calculated from `now`, preventing a backlog burst (`scheduling.py:141-169`). Existing tests cover the spring gap, first autumn fold only, skip/catch-up behavior and retry of the old cursor (`tests/test_independent_scheduling.py`). Sleep/wake was not induced in the app; this conclusion is from deterministic clock tests and code review.
- **A35 — waiting approval and compute leases: PASS, focused.** A mutation stores a scoped account/browser lease and concrete approval, moves to `waiting_for_approval`, then calls `_leave_compute` (`runtime/independent/manager.py:915-925`). That path releases the shared compute owner after safe local-AI cleanup (`manager.py:746-755`). Existing tests cover actual shared Swarm/independent slots and Swarm safe-pause release. New test holds one run at approval and proves another Space's run reaches `running` while the first retains its approval record. Account/resource ownership intentionally remains persisted for the waiting run; the released object is the compute slot.
- **A39 — Nova/Swarm governance: PASS, focused.** Independent browser admission calls the existing managed-space supervisor and receives a browser-only capability; no fallback capability is invented (`runtime/independent/governance.py:43-145`; `nova/space_supervisor.py:671`). Every provider/action passes through Nova authorization and durable claim; reviewed-execution quorum, exact consumed human approval, revision revocation, call budget and terminal release are covered by `tests/test_independent_governance.py`. Shared compute accounting and actual Swarm pause/resume release are also covered there. This does not establish every Nova workload or production account behavior.

No product-code defect was confirmed in this bounded scheduler/governance review. No product files or pre-existing tests were edited.
